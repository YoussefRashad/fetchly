# Hammel Phase 1 (the app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows desktop app that downloads a single video, a playlist, or any direct file, with quality choice, pause/resume that survives restarts, a queue, settings and a tray icon. Public content only.

**Architecture:** Electron main process owns everything with side effects: a queue that schedules jobs, two engines (yt-dlp for media, aria2 RPC for files), JSON persistence and binary management. The React renderer is a view over job state received through a typed preload API. All logic that can be pure (state machine, argument building, output parsing, naming) is pure and unit-tested; engines are tested against fake processes.

**Tech Stack:** Electron, electron-vite, TypeScript (strict), React, Vitest, ESLint. External binaries fetched at first run: `yt-dlp.exe`, `ffmpeg.exe`, `aria2c.exe`. One runtime dependency beyond React: `extract-zip`.

**Spec:** `docs/superpowers/specs/2026-11-22-download-manager-design.md` (sections: Pieces, Two kinds of job, Job states, Options, Window, Persistence, Testing; Phase 1 only)

## Global Constraints

- Windows 11, single user, no admin rights. No macOS/Linux code paths.
- Renderer has no Node access: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. It talks to main only through `window.hammel`.
- Binaries are never committed. They live in `app.getPath('userData')/bin`.
- Never re-encode video. Never attempt to decrypt protected content; report `skipped: protected`.
- Every failure or skip keeps a human-readable `reason` shown in the list. No silent drops.
- Partial data of a paused or interrupted download is never deleted (only Cancel deletes it).
- State is written to disk on every job state transition, atomically (temp file, then rename).
- Tests use no network and no real binaries.
- Default download folder: `Downloads\Hammel`. Queue limit default 3, range 1 to 8. Automatic retry 3 times.
- Phase 1 has no cookies and no extension endpoint. A login-gated item ends `failed: login required`.
- Git: work on branch `feat/phase1-app`. No remote, no push.
- Deviation from spec, deliberate: file jobs survive restarts through aria2's `.aria2` control file next to the partial file (re-adding the same URL and path continues it), not through an aria2 session file. Same behaviour, less state.

## Review Focus

1. **Titles that are not valid Windows file names** (`: ? * " < > |`, trailing dots/spaces, reserved names like `CON`, titles over 150 chars, two playlist items with the same title): files are still created, with a sanitized, truncated, unique name. Test in Task 4.
2. **Playlist containing private, deleted or region-blocked entries:** those items end `skipped` with their reason and the rest download. Tests in Task 5 (classification) and Task 8 (group continues).
3. **Network drop or PC sleep mid-download:** the job retries, then ends `failed` with partial data kept and Resume working; it never stays `downloading` with a dead process. Tests in Task 6 (process exits non-zero mid-progress) and Task 8 (retry then fail).
4. **Disk full or download folder missing/not writable:** `failed: disk full` or `failed: cannot write to folder`, no retry loop. Tests in Task 5 and Task 8.
5. **Corrupted or half-written `jobs.json`** (crash during write, manual edit): the app starts, moves the bad file to `jobs.json.corrupt-<timestamp>`, and shows an empty list. Test in Task 3.

## Shared types (defined in Task 2, used everywhere)

```ts
export type JobKind = 'media' | 'file';
export type JobState = 'queued' | 'probing' | 'downloading' | 'paused' | 'merging' | 'done' | 'failed' | 'skipped';
export type Height = 2160 | 1440 | 1080 | 720 | 480 | 360;
export type Quality =
  | { kind: 'best' }
  | { kind: 'max'; height: Height }
  | { kind: 'audio'; format: 'm4a' | 'mp3' };

export interface Job {
  id: string; groupId: string | null; kind: JobKind; url: string; title: string;
  state: JobState; reason: string | null;
  quality: Quality | null;          // null for file jobs
  subtitleLangs: string[];
  dir: string; fileName: string | null; index: number | null; // index: 1-based position in group
  bytesDone: number; bytesTotal: number | null; speed: number; eta: number | null;
  actualHeight: number | null; resumable: boolean; attempts: number; createdAt: number;
}
export interface Group { id: string; title: string; url: string; dir: string; createdAt: number; }

export interface Settings {
  downloadDir: string; askEveryTime: boolean; maxConcurrent: number; // 1..8
  speedLimitKbps: number;            // 0 = unlimited
  autoResumeOnStart: boolean; preferMp4Max1080: boolean;
  defaultQuality: Quality; subtitleLangs: string[];
}

export type ProbeResult =
  | { kind: 'media'; title: string; thumbnail: string | null; heights: number[] }
  | { kind: 'playlist'; title: string; entries: { index: number; url: string; title: string; unavailable: boolean }[] }
  | { kind: 'file'; fileName: string; size: number | null; resumable: boolean };

export interface AddRequest {
  url: string; probe: ProbeResult; quality: Quality | null; subtitleLangs: string[];
  dir: string; selectedIndexes: number[] | null; // playlist only
}
export type JobVerb = 'pause' | 'resume' | 'cancel' | 'retry' | 'remove' | 'removeWithFile';
export type GroupVerb = 'pause' | 'resume' | 'cancel';
export interface Snapshot { jobs: Job[]; groups: Group[]; }
```

  ```ts
  export type JobEvent =
    | { type: 'start' } | { type: 'firstProgress' } | { type: 'merging' }
    | { type: 'done'; fileName: string; actualHeight: number | null }
    | { type: 'pause' } | { type: 'resume' } | { type: 'retry' }
    | { type: 'fail'; reason: string } | { type: 'skip'; reason: string };

  export const ACTIVE: ReadonlySet<JobState>; // probing, downloading, merging
  ```

Transition table (anything else throws):

| From | Event | To |
|---|---|---|
| queued | start | probing |
| probing | firstProgress | downloading |
| probing, downloading | merging | merging |
| probing, downloading, merging | done | done |
| queued, probing, downloading | pause | paused |
| paused | resume | queued |
| failed | retry | queued (attempts reset to 0) |
| queued, probing, downloading, merging | fail | failed |
| queued, probing, downloading | skip | skipped |

`fail`/`skip` set `reason`; `resume`/`retry` clear it; `done` sets `fileName`, `actualHeight`, `speed: 0`, `eta: null`. Pausing during `merging` is illegal (the merge takes seconds; the UI disables the button).

### Task 4: Naming and yt-dlp arguments

**Files:**
- Create: `src/main/naming.ts`, `src/main/ytdlp/args.ts`
- Test: `tests/naming.test.ts`, `tests/ytdlp/args.test.ts`

**Interfaces:**
- Produces:
  ```ts
  // naming.ts
  export function sanitizeName(raw: string): string;
  export function itemBaseName(title: string, index: number | null, total: number | null): string;
  export function uniqueName(base: string, ext: string, taken: ReadonlySet<string>): string; // case-insensitive
  // args.ts
  export const PROGRESS_PREFIX = 'HAMMEL_PROGRESS';
  export const FILE_PREFIX = 'HAMMEL_FILE';
  export function probeArgs(url: string): string[];
  export function downloadArgs(o: {
    url: string; quality: Quality; preferMp4Max1080: boolean; subtitleLangs: string[];
    dir: string; baseName: string; ffmpegPath: string; rateLimitBytes: number | null;
  }): string[];
  ```

Rules:
- `sanitizeName`: replace each of `\ / : * ? " < > |` and control characters with a space, collapse whitespace, strip trailing dots and spaces, truncate to 150 characters, prefix `_` to Windows reserved names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9`, `LPT1`-`LPT9`, any case), and return `untitled` when the result is empty.
- `itemBaseName`: no index gives the sanitized title. With an index: `NN - title`, zero-padded to the width of `total` (minimum 2), so item 3 of 40 is `03 - title` and item 3 of 120 is `003 - title`.
- `uniqueName`: `base.ext`, else `base (2).ext`, `base (3).ext`, ...
- `probeArgs`: `['-J', '--flat-playlist', '--no-warnings', url]`.
- `downloadArgs` always includes: `--no-playlist`, `--newline`, `--progress`, `--no-warnings`, `--continue`, `--no-overwrites`, `--retries 3`, `--ffmpeg-location <ffmpegPath>`, `-P <dir>`, `-o <baseName>.%(ext)s`, `--progress-template download:HAMMEL_PROGRESS %(progress.downloaded_bytes)s %(progress.total_bytes)s %(progress.total_bytes_estimate)s %(progress.speed)s %(progress.eta)s`, `--print after_move:HAMMEL_FILE %(height)s %(filepath)s`, and the url last.
- Format, by quality (H = ceiling):
  - `max` with H <= 1080, or `best` with `preferMp4Max1080` (then H = 1080): `-f bv*[height<=H][vcodec^=avc1]+ba[acodec^=mp4a]/bv*[height<=H]+ba/b[height<=H]`, `--merge-output-format mp4`.
  - `max` with H > 1080 and not `preferMp4Max1080`: `-f bv*[height<=H]+ba/b[height<=H]`, `--merge-output-format mkv`. With `preferMp4Max1080`, treat as H = 1080 (first rule).
  - `best` without `preferMp4Max1080`: `-f bv*+ba/b`, `--merge-output-format mkv`.
  - `audio`: `-f ba/b`, `-x`, `--audio-format <m4a|mp3>`; no `--merge-output-format`.
- `subtitleLangs` non-empty adds `--write-subs --sub-langs <comma-joined>`. `rateLimitBytes` non-null adds `--limit-rate <n>`.

### Task 5: Parsing yt-dlp output

**Files:**
- Create: `src/main/ytdlp/parse.ts`
- Test: `tests/ytdlp/parse.test.ts`

**Interfaces:**
- Consumes: `PROGRESS_PREFIX`, `FILE_PREFIX`, `ProbeResult`.
- Produces:
  ```ts
  export function parseProbe(json: string): Extract<ProbeResult, { kind: 'media' | 'playlist' }>; // throws on invalid JSON
  export type Line =
    | { type: 'progress'; bytesDone: number; bytesTotal: number | null; speed: number; eta: number | null }
    | { type: 'file'; height: number | null; path: string }
    | { type: 'merging' } | { type: 'other' };
  export function parseLine(line: string): Line;
  export function classifyError(stderr: string): { outcome: 'failed' | 'skipped'; reason: string; retryable: boolean };
  ```

Rules:
- `parseProbe`: `_type === 'playlist'` gives `kind: 'playlist'`, entries in order with 1-based `index`, `url` from `url` or `webpage_url`, `unavailable: true` when the title is `[Private video]` or `[Deleted video]` or the entry has no url; a `null` entry is dropped. Otherwise `kind: 'media'`, `heights` = distinct numeric `formats[].height`, descending; missing `formats` gives `[]`.
- `parseLine`: a progress line has five space-separated fields after the prefix; `NA` means unknown. `bytesTotal` is `total_bytes`, else `total_bytes_estimate`, else `null`. Unknown speed is `0`. A file line: first field height (or `NA`), the rest of the line is the path (paths contain spaces). A line starting `[Merger]` or `[ExtractAudio]` is `merging`.
- `classifyError`, first match wins, case-insensitive, against the whole stderr:

| Pattern | Outcome | Reason | Retryable |
|---|---|---|---|
| `DRM` | skipped | protected | no |
| `Private video` | skipped | private | no |
| `Video unavailable`, `has been removed`, `account .* terminated`, `does not exist` | skipped | removed | no |
| `not available in your country`, `geo.?restrict` | skipped | unavailable in region | no |
| `Sign in`, `log in`, `login required`, `cookies`, `members-only`, `age` + `confirm` | failed | login required | no |
| `No space left`, `ENOSPC`, `not enough space` | failed | disk full | no |
| `Permission denied`, `EACCES`, `EPERM`, `unable to open for writing` | failed | cannot write to folder | no |
| `Unsupported URL` | failed | unsupported site | no |
| anything else | failed | text of the last line starting `ERROR:` without that prefix, or `download failed` | yes |

### Task 6: Media engine

**Files:**
- Create: `src/main/engines/engine.ts`, `src/main/engines/media.ts`, `tests/fakes/fake-ytdlp.mjs`
- Test: `tests/engines/media.test.ts`

**Interfaces:**
- Consumes: `downloadArgs`, `parseLine`, `classifyError`, `itemBaseName`.
- Produces:
  ```ts
  // engine.ts
  export type EngineEvent = { jobId: string } & (
    | { type: 'progress'; bytesDone: number; bytesTotal: number | null; speed: number; eta: number | null }
    | { type: 'merging' }
    | { type: 'done'; fileName: string; actualHeight: number | null }
    | { type: 'error'; outcome: 'failed' | 'skipped'; reason: string; retryable: boolean });
  export interface StartContext { settings: Settings; groupSize: number | null; rateLimitBytes: number | null; }
  export interface Engine {
    start(job: Job, ctx: StartContext): void;
    stop(jobId: string): Promise<void>;          // keeps partial data; no event is emitted for a stopped job
    discard(job: Job): Promise<void>;            // stop if running, then delete partial files
    on(listener: (ev: EngineEvent) => void): void;
  }
  // media.ts
  export interface Exe { command: string; prefixArgs: string[]; }
  export class MediaEngine implements Engine { constructor(ytdlp: Exe, ffmpegPath: string); }
  ```

Behaviour:
- One child process per job, spawned with `windowsHide: true`. stdout is split on newlines and fed to `parseLine`; stderr is accumulated (cap 64 KB, keep the tail).
- Exit code 0 with a `file` line seen: emit `done` with the base name of the path and the height. Exit 0 without a `file` line: `error` failed, reason `finished without a file`, not retryable.
- Non-zero exit: emit `error` from `classifyError(stderr)`.
- `stop`: mark the job as stopping, kill the whole process tree with `taskkill /PID <pid> /T /F` (yt-dlp spawns ffmpeg), resolve when the child's `exit` fires. Nothing is emitted for it.
- `discard`: after stopping, delete files in `job.dir` whose name starts with the job's base name and ends with `.part`, `.ytdl`, or matches `.f<digits>.<ext>` (unmerged streams). Never delete a file that lacks one of those suffixes.
- A spawn error (binary missing) emits `error` failed, reason `yt-dlp is not installed`, not retryable.

`fake-ytdlp.mjs` is run as `{ command: process.execPath, prefixArgs: ['tests/fakes/fake-ytdlp.mjs'] }`. It reads a scenario from env `FAKE_YTDLP`: `ok` (prints three progress lines, a `[Merger]` line, a `HAMMEL_FILE 1080 <dir>\<base>.mp4` line built from its `-P` and `-o` args, exit 0), `drop` (two progress lines, writes `<base>.mp4.part`, prints `ERROR: unable to download video data: HTTP Error 503` to stderr, exit 1), `private` (stderr `ERROR: [youtube] x: Private video`, exit 1), `hang` (writes the `.part` file, prints progress every 50 ms forever), `nofile` (exit 0, nothing printed).

- `startAria2` spawns `aria2c --enable-rpc --rpc-listen-all=false --rpc-listen-port=<free port> --rpc-secret=<random 32 hex> --continue=true --max-connection-per-server=8 --split=8 --min-split-size=1M --auto-file-renaming=false --allow-overwrite=false --max-tries=3 --retry-wait=5`, picks the free port by binding port 0 first, and waits until `aria2.getVersion` answers (20 tries, 250 ms apart). The RPC client POSTs JSON-RPC to `http://127.0.0.1:<port>/jsonrpc` with `token:<secret>` as the first param.
- `start(job)`: `aria2.addUri([[url], { dir: job.dir, out: job.fileName }])`, remember the gid, poll `aria2.tellStatus(gid, ['status','completedLength','totalLength','downloadSpeed','errorCode','errorMessage'])`. `active` emits progress (eta = remaining/speed, `null` when speed is 0); `complete` emits `done` with `actualHeight null`; `error` emits `error` mapped by aria2 `errorCode`: 9 gives `disk full`, 15/16/17/18 give `cannot write to folder`, 3 gives `file not found on server`, 24 gives `login required`, 13 gives `file already exists`; all of those not retryable; any other code is failed, retryable, reason = `errorMessage`.
- `stop`: `aria2.forcePause(gid)` then `aria2.remove(gid)`; the partial file and its `.aria2` control file stay, so a later `start` with the same `dir`/`out` continues. `discard`: stop, then delete `<file>` and `<file>.aria2`, only if the `.aria2` control file exists (a finished file is never deleted here).
- `validateUrl`: trims, accepts only `http:` and `https:`; anything else throws `InvalidUrl`.
- `probeUrl`: run `yt-dlp` with `probeArgs` (timeout 30 s). On exit 0, `parseProbe`. Exception: when yt-dlp's result has `extractor` equal to `generic` and `direct === true`, treat it as a file. On non-zero exit whose stderr classifies as anything other than `unsupported site`, rethrow as `ProbeError` carrying `{ outcome, reason }` (so "private" or "login required" is shown in the add dialog rather than falling through to a file download). Otherwise file probe: `GET` with header `Range: bytes=0-0`; status 206 means `resumable: true` and size from `Content-Range`; status 200 means `resumable: false` and size from `Content-Length`; any other status throws `ProbeError` reason `server answered <status>`. If the response `Content-Type` starts with `text/html`, throw `ProbeError` reason `this link is a web page, not a file`. File name: `Content-Disposition` filename, else the last URL path segment (decoded), else `download`; then `sanitizeName` on the stem.

`fake-aria2.ts` implements `Aria2Rpc` in process: scripted status sequences per gid, records every call.

**Files:**
- Create: `src/main/jobs/queue.ts`
- Test: `tests/jobs/queue.test.ts`

**Interfaces:**
- Consumes: `transition`, `ACTIVE`, `Store`, `Engine`, `EngineEvent`, `AddRequest`, `itemBaseName`, `uniqueName`, `sanitizeName`.
- Produces:
  ```ts
  export class Queue {
    constructor(deps: {
      store: Store; media: Engine; file: Engine & { setGlobalLimit(n: number): Promise<void> };
      initial: Snapshot; settings: Settings;
      now?: () => number; setTimer?: (fn: () => void, ms: number) => unknown;
    });
    snapshot(): Snapshot;
    add(req: AddRequest): void;
    job(id: string, verb: JobVerb): Promise<void>;
    group(id: string, verb: GroupVerb): Promise<void>;
    setSettings(s: Settings): void;
    resumeAllPaused(): void;                         // used for autoResumeOnStart
    onChanged(listener: (s: Snapshot) => void): void; // progress changes throttled to one call per 250 ms; state changes immediate
    onFinished(listener: (e: { kind: 'job' | 'group'; title: string; failed: number; skipped: number }) => void): void;
  }
  export const RETRY_DELAYS_MS = [5000, 20000, 60000];
  ```

Behaviour:
- `add`: a `media` probe makes one job; a `file` probe makes one job with `fileName` set through `uniqueName` against existing jobs in the same `dir` and files on disk; a `playlist` probe makes a `Group` whose `dir` is `join(req.dir, sanitizeName(title))` and one job per selected entry with `index` = the entry's playlist index. Entries marked `unavailable` are added already `skipped` with reason `unavailable`, so the list shows them. All others start `queued`.
- Scheduling: after every change, while the count of `ACTIVE` jobs is below `maxConcurrent`, start the oldest `queued` job (`createdAt`, then `index`). Starting applies `start` and calls the engine for its kind.
- Media rate limit: `speedLimitKbps === 0` gives `null`; otherwise `floor(speedLimitKbps * 1024 / maxConcurrent)` per media job. File jobs use `file.setGlobalLimit(speedLimitKbps * 1024)`, called on construction and on `setSettings`.
- Engine events map to transitions: first `progress` on a `probing` job applies `firstProgress`; `merging`, `done`, `error` as named. An event for a job that is not `ACTIVE` is ignored.
- Retry: on `error` with `outcome 'failed'` and `retryable` and `attempts < 3`: increment `attempts`, set state back to `queued` with `reason` `retrying (n/3)` after `RETRY_DELAYS_MS[attempts - 1]`; while waiting the job holds no slot. Otherwise apply `fail`/`skip`. A successful `done` leaves `attempts` as is.
- Verbs: `pause` stops the engine if active then applies `pause`; `resume` applies `resume`; `retry` applies `retry`; `cancel` calls `engine.discard` and removes the job from the list; `remove` deletes a finished/failed/skipped job from the list only; `removeWithFile` also deletes `join(dir, fileName)` when the job is `done`. Group verbs apply the job verb to every member where it is legal and skip the others; `cancel` on a group also removes the group.
- A group is finished when no member is `queued`, `ACTIVE` or `paused`; fire `onFinished` once with the counts. A lone job fires on `done` or final `failed`.
- Every state change calls `store.saveSnapshot`. Progress-only changes are saved at most once every 5 s.
- A group with zero remaining jobs is removed.
