# PF-1 results (run 2026-11-24 by the orchestrator)

Environment: Windows (Version 10.0.26100.8037]), Electron 45.4.1 (Chrome 156.0.8078.100), Vite 8.3.8 (the repository's), @fontsource/ibm-plex-sans 5.3.0 and @fontsource/ibm-plex-sans-arabic 5.3.0 (both OFL-1.1, npm registry). electron-vite 6.0.0 is the repository's; the probe used plain Vite 8.3.8 with base './' (what electron-vite's renderer build uses), in a scratch project outside the repository, one process.

1. Package names exist; current version 5.3.0 for both.
2. Subset CSS files exist: '@fontsource/ibm-plex-sans/latin-400.css', 'latin-500.css', 'latin-600.css'; '@fontsource/ibm-plex-sans-arabic/arabic-400.css', 'arabic-500.css', 'arabic-600.css'. Each declares one @font-face with font-display: swap and src: url(./files/<name>.woff2) format('woff2'), url(./files/<name>.woff) format('woff'). The arabic-*.css files carry no unicode-range line (the full arabic subset file applies to every character it covers).
3. With build.assetsInlineLimit: 0, the build emitted each font as a separate hashed file in dist/assets (both .woff2 and .woff, because both are referenced): woff2 sizes latin 400/500/600 = 22.6/24.2/24.3 kB, arabic 400/500/600 = 42.8/45.3/45.7 kB (woff2 total ~205 kB); the .woff copies add ~208 kB more. The CSS bundle holds no "data:" (grep count 0); URLs are relative (url(./ibm-plex-sans-latin-400-normal-<hash>.woff2)).
4. Loaded from file:// in Electron 45.4.1 (sandbox true, contextIsolation true) with the app's exact CSP meta (default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' https: data:): no console message (no CSP violation); document.fonts.check("400 16px 'IBM Plex Sans Arabic'", 'قيد') = true and ("600 16px 'IBM Plex Sans'", 'Downloading') = true; faces used on the page report "loaded", unused weights stay "unloaded" (lazy, as expected). No network request is involved: every font URL is a relative file.
5. Not probed: electron-vite's own renderer build (same Vite version; C1's gate "npm run build then check out/renderer/assets" covers it in the real build).

Consequence for C1: package names and paths in the architecture plan are confirmed. Option for C1's plan to decide: import the subset CSS as is (ships woff + woff2, ~413 kB) or write its own @font-face rules pointing at files/*.woff2 only (~205 kB; Chromium 156 supports woff2).
